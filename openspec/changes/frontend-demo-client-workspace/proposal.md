# Proposal

## Why

Dev 2 ещё не опубликовал HTTP API. Пользователь разрешил реализовать первые шесть frontend-фич на изолированных заглушках без ручного ревью. Основание: ARCHITECTURE §Dev 3, SPEC §4 (оформление и проверка заявки), §5 Q55 (единый интерфейс двух ролей). Демо не считается завершением интеграции с API.

## What Changes

- Явные mock/api режимы с изолированным адаптером данных, задержками, ошибками и сбросом.
- Подключённая LoginView, демо-учётки, подтверждение роли адаптером, выход и защита маршрутов.
- Генерируемые из домена статусы, StatusBadge и Timeline.
- Кабинет с профилем, продуктами и заявками.
- Форма заявки с валидацией, согласиями, черновиком и подачей.
- Страница заявки с историей и опросом ожидающих состояний.

## Capabilities

### New Capabilities

- `demo-client-workspace`: воспроизводимый клиентский путь до результата скоринга на явно включённых моках.

### Modified Capabilities

- `user-auth`: различить реальный API и разрешённый mock-вход.
- `workspace-navigation`: заменить предварительный просмотр защищённым демо-кабинетом в mock-режиме.
- `client-credit-application`: разрешить изолированные демонстрационные данные без объявления HTTP-интеграции завершённой.

## Impact

Frontend, генератор фикстур/типов из существующего Python-домена, README и тесты. Новых зависимостей нет; HTTP API и модель БД не меняются. Режим API до передачи контракта явно недоступен, без придуманного HTTP DTO или скрытого fallback.

## Вне скоупа

Фичи 7–14: офферы и факторы решения, подписание, симулятор, полноценные банковские экраны/метрики. Финансовая арифметика в JS, реальные внешние интеграции и готовность production API не заявляются.
