# Design

## Context

Существуют providers, LoginView, layout, транспорт, форматтеры и общие feedback-компоненты. Маршруты пока заглушки. HTTP API отсутствует; backend уже содержит seed, продукты, FSM и результаты скоринга. Пользователь разрешил явные frontend-моки и автоматическое выполнение всего цикла OpenSpec.

## Goals / Non-Goals

**Goals:** шесть последовательных фич, пригодных для ручного прохождения и последующей адаптации к HTTP.

**Non-Goals:** финансовые расчёты/скоринг JS, изменение backend API/БД, фичи 7–14 и проверка полной выдачи.

## Decisions

1. Один интерфейс WorkspaceGateway для представлений UI. Типы — временные модели представления, не ручная имитация schema.d.ts. MockGateway изолирован; API-режим до появления OpenAPI возвращает понятную недоступность вместо выдуманных HTTP-вызовов. Переключение режима очищает сессию и кеш. По умолчанию mock, видна постоянная плашка.
2. scripts/export_frontend_demo.py генерирует JSON и TS-союзы статусов из backend seed, POLICY_V1 и application_status. Истории проверяются Python FSM; frontend только воспроизводит стадии. Для произвольных условий итог демо — ручное рассмотрение, а не рассчитанное одобрение. Seed не копируется вручную. Артефакты включают только публичный профиль и данные сценария, без банковской трассы.
3. Настройки задержки/одноразовых ошибок находятся внутри mock-адаптера. Асинхронные чтения отменяются AbortSignal, мутации защищены от дублей и сброса поколения. Записи привязаны компании; роль проверяется адаптером и RequireRole. AuthProvider поверх существующей памяти session и QueryClient, query keys включают пользователя/режим/поколение.
4. LoginPage использует LoginView и отдельные кнопки демо-персон из адаптера. Роль не выбирается подписью формы. Refresh очищает сессию; returnTo допускает только собственный контур. Демо-пароль demo, только в памяти, реальные пароли не логируются.
5. TanStack Query для независимых секций кабинета и страницы заявки. Форма содержит Alfa Input/Button, native select/checkbox с подписями; деньги проверяются строковыми операциями без Number/parseFloat. Ограничения и шаги приходят из экспорта политики. Черновик сохраняется отдельно от submit; при повторе после ошибки submit уже созданный draft переиспользуется с version.
6. StatusBadge имеет exhaustive mapping сгенерированного союза. Timeline отображает фактические события, не проценты. Опрос 1500 мс только SUBMITTED/SCORING; отключается при error, logout, уходе и результате. APPROVED/COUNTER_OFFER/REJECTED/UNDERWRITING показаны как результат демо, подробные панели фич 7–10 остаются вне скоупа.
7. Desktop 1280/1440, Alfa Typography/Button/Input без новых зависимостей. Полный набор тестов адаптера, auth, формы, таймлайна, опроса/сброса и реальный браузерный проход. Старые тесты preview заменяются тестами текущей защищённой навигации, проверки не отключаются.

## API и модель данных

HTTP endpoint и backend-модели не меняются. Не создаётся docs/openapi.json. Будущий API-адаптер преобразует generated DTO в WorkspaceGateway; mock-файлы не выдаются за реальный контракт. Финансовые правила, факторы, веса и пороги остаются в существующем домене.

## Risks / Trade-offs

- Различия будущего API → изолированный gateway и явная отметка незавершённой интеграции.
- Гонки logout/reset → отмена чтений, поколение mock-state и проверки актуальности сессии.
- Потеря памяти при refresh → подсказка в демо и повторный вход, без постоянного хранения токенов/банковских данных.

## Migration Plan

Реализовать шесть задач по порядку с отдельными коммитами, проверить harness/build/browser, синхронизировать дельты и архивировать. Откат — revert frontend-коммитов. Для API потребуется отдельный change после экспорта Dev 2.
