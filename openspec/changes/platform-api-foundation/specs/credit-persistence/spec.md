## Requirements

### Requirement: История статусов
Система SHALL сохранять каждое изменение статуса заявки вместе с актором, временем и причиной в одной транзакции с заявкой.

#### Scenario: Переход заявки
- **WHEN** сервис переводит заявку в новый статус
- **THEN** текущий статус и запись истории коммитятся атомарно.

### Requirement: Optimistic locking
Команды заявки SHALL проверять поле `version` и отклонять устаревшую команду.

#### Scenario: Двойная команда
- **WHEN** две команды используют одну старую версию заявки
- **THEN** одна команда получает успех, а другая HTTP 409 с `VERSION_CONFLICT`.
