# Spec Delta

## Purpose

Обеспечить единое проверяемое взаимодействие веб-интерфейса с локальным API, предсказуемые ошибки и безопасное подключение будущего опубликованного контракта без дублирования доменной логики.

## ADDED Requirements

### Requirement: Локальные запросы

HTTP-слой SHALL отправлять запросы через относительный префикс `/api/v1`, передавать JSON без изменения денежных строк и добавлять Bearer-токен только при наличии сессии. Он SHALL поддерживать отмену запроса и не отправлять токен на произвольные внешние адреса.

#### Scenario: Запрос с токеном
- **WHEN** вызывающая сторона отправляет JSON с суммой `"2500000.00"` и текущим токеном
- **THEN** локальный API получает неизменённую строку суммы и заголовок Authorization с Bearer-токеном

#### Scenario: Запрос без сессии
- **WHEN** выполняется запрос при отсутствии токена
- **THEN** заголовок Authorization отсутствует

#### Scenario: Запрещённый внешний адрес
- **WHEN** вызывающая сторона передаёт абсолютный URL либо путь с выходом из префикса API
- **THEN** запрос отклоняется до обращения к сети и токен никуда не отправляется

#### Scenario: Отмена запроса
- **WHEN** вызывающая сторона отменяет ожидающий запрос
- **THEN** запрос завершается как отменённый и не выдаётся за успешный или новую ошибку сервера

### Requirement: Успешные ответы

HTTP-слой SHALL возвращать разобранный JSON для успешного JSON-ответа и отсутствие значения для ответа 204. Некорректный JSON в ожидаемом JSON-ответе SHALL приводить к контролируемой ошибке протокола.

#### Scenario: Ответ без содержимого
- **WHEN** API возвращает 204 без тела
- **THEN** запрос успешно завершается без попытки разбора пустого тела как JSON

#### Scenario: Повреждённый JSON
- **WHEN** API возвращает успешный HTTP-статус с некорректным JSON
- **THEN** вызывающая сторона получает контролируемую ошибку протокола

### Requirement: Предсказуемые ошибки

HTTP-слой SHALL сохранять HTTP-статус и доступные поля `code`, `message`, `details` ошибки API. Сетевые ошибки и ответы без корректного JSON SHALL иметь безопасное резервное сообщение. Текст HTML и необработанные объекты SHALL не отображаться как сообщение пользователю.

#### Scenario: Конфликт версии
- **WHEN** API возвращает 409 с `code=VERSION_CONFLICT`
- **THEN** вызывающая сторона получает этот статус, код и детали без автоматического повторения операции

#### Scenario: Валидация или запрет доступа
- **WHEN** API возвращает 422 либо 403 с корректной ошибкой
- **THEN** HTTP-слой сохраняет статус и описание, не сбрасывая текущую сессию

#### Scenario: Сетевая ошибка
- **WHEN** локальный API недоступен
- **THEN** вызывающая сторона получает контролируемую сетевую ошибку с понятным сообщением

#### Scenario: Ответ прокси вместо JSON
- **WHEN** сервер возвращает 502 с HTML-телом
- **THEN** вызывающая сторона получает статус 502 и резервное сообщение без HTML

### Requirement: Истечение сессии

При ответе 401 HTTP-слой SHALL уведомлять владельца сессии, чтобы тот удалил токен, очистил кеш данных и перенаправил пользователя на страницу входа. Автоматическое повторение отклонённого запроса SHALL не выполняться.

#### Scenario: Неавторизованный ответ
- **WHEN** запрос текущей сессии возвращает 401
- **THEN** токен и кеш удаляются, открывается страница входа, а запрос не повторяется

### Requirement: Контракт без выдуманных DTO

Подключение бизнес-типов SHALL опираться на опубликованный OpenAPI backend. При отсутствии схемы команда генерации SHALL завершаться понятной ошибкой без создания фиктивных DTO. Отсутствие схемы SHALL не блокировать сборку и тесты каркаса, который ещё не использует бизнес-типы.

#### Scenario: Схема ещё не опубликована
- **WHEN** разработчик запускает генерацию без `docs/openapi.json`
- **THEN** команда сообщает, что нужен экспорт Dev 2, возвращает ненулевой код и не создаёт заглушечный файл типов

#### Scenario: Схема опубликована
- **WHEN** разработчик запускает генерацию с валидным экспортом backend
- **THEN** типы создаются из этого экспорта без ручного переписывания денежных типов, DTO и перечислений

### Requirement: Изоляция тестирования

Проверки HTTP-слоя SHALL выполняться с детерминированными синтетическими ответами без работающего backend и реальных интеграций ФНС, БКИ или банка. Финансовые расчёты и решения SHALL оставаться вне HTTP-слоя.

#### Scenario: Изолированная проверка
- **WHEN** тесты каркаса запускаются без backend и внешних сервисов
- **THEN** запросы проверяются на подменённом транспорте, а обращения к реальным внешним системам отсутствуют
