# Tasks

Все задачи относятся к Dev 3. Оценки — рабочие интервалы по 30–90 минут. После правок выполнять harness_quick_check; отметки ниже заполняются только при apply. Полный бизнес-сценарий и реальный вход остаются отдельным изменением.

## 1. Основа frontend

- [ ] 1.1 (60–90 мин) Создать frontend на React 18 + TypeScript strict + Vite; подключить совместимые Alfa Core Components, TanStack Query, react-router, ESLint, Vitest, jsdom и Testing Library. Проверить peerDependencies и документированные импорты/CSS без обхода конфликтов. Настроить единый tsconfig, игноры eslint и npm-скрипты из design.md; сохранить package-lock.json и сразу обновить THIRD_PARTY_NOTICES.md. Критерий: `cd frontend && npm ci && npm run lint && npm run typecheck && npm run build`, вывод `npm ls react react-dom @alfalab/core-components` без invalid peer dependencies.
- [ ] 1.2 (30–60 мин) Создать корневые провайдеры QueryClient/сессии и тестовое окружение с изолированным кешем; отключить автоматический retry. Документировать запуск и ограничения каркаса в frontend/README.md. Критерий: smoke-тест рендера проходит через `npm run test -- --run`, повторный рендер сохраняет QueryClient, новые тесты не наследуют кеш предыдущих; команда запуска из README открывает frontend без backend.

## 2. Desktop layout и маршруты

- [ ] 2.1 (60–90 мин) Реализовать AppLayout на Alfa-компонентах, обозначение предварительного просмотра, меню обоих контуров и все маршруты из таблицы design.md, включая приоритет `/new`, параметры, корневой redirect и 404. Добавить рядом тесты переходов, активной навигации, прямого открытия, placeholder-текстов и отсутствия запросов. Критерий: `npm run test -- --run` и `npm run build` проходят; заглушки не показывают фиктивные учётные данные/решения, формы входа и операции отсутствуют.
- [ ] 2.2 (30–60 мин) Проверить и при необходимости поправить desktop-вёрстку, семантику и фокус; дополнить README результатами проверки. Критерий: при ширинах 1280 и 1440 меню/контент не перекрываются, Tab/Enter работают, refresh вложенной страницы в Vite возвращает нужную заглушку, консоль без ошибок. Автоматические проверки названий landmarks/ссылок и aria-current проходят; мобильные breakpoint не добавлены.

## 3. HTTP-слой и сессия

- [ ] 3.1 (60–90 мин) Реализовать fetch-обёртку и ApiError, прокси `/api` на `localhost:8000`, защиту относительных API-путей, AbortSignal и обработку JSON/204. Одновременно добавить тесты подменённого fetch: токен/его отсутствие, денежная строка, 200/204, повреждённый JSON, внешние адреса/выход из префикса, сеть и отмена. Описать контракт транспорта и настройку proxy в frontend/README.md. Критерий: соответствующие Vitest-тесты, eslint и typecheck проходят без реального API.
- [ ] 3.2 (60–90 мин) Подключить обработку 401 к владельцу сессии: удаление токена, отмена и очистка QueryClient, переход на `/login`; защитить новую сессию от устаревшего 401. Добавить интеграционные тесты сброса/перенаправления и отсутствия сброса при 403/409/422; проверить JSON-ошибки и 502 с HTML, запрет retry. Критерий: тесты проходят с детерминированными ответами, отсутствуют токены в localStorage/логах и повторные банковские команды; README объясняет, что реального входа и RBAC пока нет.

## 4. Подключение контракта

- [ ] 4.1 (30–60 мин) Добавить `npm run gen:api` через openapi-typescript для `../docs/openapi.json` → `src/api/schema.d.ts`, с понятной ошибкой при отсутствии файла и атомарной заменой результата. Протестировать генератор на временной минимальной схеме, отсутствие входа и сохранность прежнего выхода при ошибке. Описать передачу OpenAPI от Dev 2 в README. Критерий: тесты генератора проходят; без схемы gen:api возвращает ненулевой код и понятное сообщение, а build/typecheck/test каркаса проходят; ручных DTO, копий personas и фиктивного docs/openapi.json нет.

## 5. Интеграционная проверка

- [ ] 5.1 (30–60 мин) Прогнать scripts/check.sh, обновить docs/openapi.json и THIRD_PARTY_NOTICES.md. Критерий: `harness_check` возвращает `exit 0`, `cd frontend && npm ci && npm run build && npm run test -- --run` проходит, `openspec validate frontend-shell --strict` проходит. THIRD_PARTY_NOTICES.md соответствует lock-файлу. Если API всё ещё отсутствует, docs/openapi.json не создавать и не подменять: зафиксировать этот факт в отчёте; если Dev 2 опубликовал API, получить его экспорт через штатную проверку и проверить gen:api, не меняя backend-контракт. Проверить Git-ignore новых артефактов перед будущим коммитом; коммит только по отдельной просьбе пользователя.

## Workflow follow-up

- После просмотра и явного запуска пользователем применить изменение через openspec-apply-change.
- Архивировать и синхронизировать основные спецификации только после реализации и успешных проверок через openspec-archive-change.
- Следующее изменение: реальный вход, role guards и клиентский путь против опубликованного stub API Dev 2.
