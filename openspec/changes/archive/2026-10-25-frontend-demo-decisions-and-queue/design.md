# Design

## Context

Первые шесть фич используют WorkspaceGateway, scoped TanStack Query и сгенерированные seed/FSM-истории. HTTP API/OpenAPI отсутствуют. Пользователь разрешил mock-first и последовательное применение без ревью.

## Goals / Non-Goals

Цель: фичи 7–11, полный демо-путь P1 до выдачи, альтернативы P2/P3, отказ P4 и очередь bank. Не цель: №12–14, HTTP-интеграция или production-подпись.

## Decisions

1. Генератор экспортирует client-safe решения/офферы, тексты факторов без points/source/rule/value, конечную сетку simulate и FSM-шаблоны SIGNING/SIGNED/DISBURSED/EXPIRED. Decimal остаются строками. Без JS-скоринга и второго графа переходов.
2. HTTP эндпоинты и docs/openapi.json не меняются. Временная UI-модель дополняется Decision, Offer, SigningChallenge, Simulation, QueueItem. WorkspaceGateway получает accept/challenge/sign/simulate/queue. API-адаптер остаётся unavailable; будущие DTO будут сгенерированы Dev 2.
3. Mock хранит выбранный оффер, challenge (демо-код, TTL 5 мин, 3 попытки), время подписи; проверяет owner/version/status/expiry после задержки. SIGNED выдаёт DISBURSED через чтение спустя 1,5 с. События берутся из Python-шаблонов; ID/время привязываются к записи.
4. Срок оффера в демо 30 мин от решения. Истечение возвращает EXPIRED по сгенерированному событию. Результат accept возвращается в application-кеш; challenge восстанавливается отдельным чтением. После 409 перечитать, не повторять. Формы блокируют повтор и игнорируют ответ после unmount/logout/reset.
5. Simulator: ввод суммы-строки/срока, debounce 300 мс, signal cancellation и ключ по комбинации. Python заранее вычисляет небольшой набор сумм (запрос/альтернативы/мин/половина) и все допустимые сроки. Другие суммы показывают «нет демо-расчёта». Это сознательный предел mock, не подмена произвольного расчёта. Симуляция не создаёт/не меняет офферы заявки.
6. Queue: отдельный scoped query только bank, синтетические заявки шести персон плюс текущие records, фильтры/поиск/стабильная сортировка. Точное сравнение денежных строк для сортировки через BigInt, без финансовой математики. Досье — честная заглушка.
7. Скоринг не меняется: факторы/веса/пороги берёт Python POLICY_V1, M1 20/M2 20/M3 25/M4 15/M5 20; knockout имеет приоритет, DSCR_min 1,3. Никаких новых таблиц порогов в JS. Клиентские тексты рендерит explain.py.

## Risks / Trade-offs

Сетка конечна; это явно указано рядом с симулятором. Демо-код показывается в UI и хранится только в памяти — не production security. Перезагрузка теряет сессию/заявки. Нет реальной выдачи; DISBURSED помечен демо. Независимая проверка gateway, гонок query/команд, ролей, expiry и browser flow обязательна.
