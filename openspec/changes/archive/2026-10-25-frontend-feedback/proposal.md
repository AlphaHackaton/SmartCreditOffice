# Proposal

## Why

После форматтеров следующая доступная без API часть общих компонентов Dev 3 — ErrorBanner и ConfirmDialog (ARCHITECTURE:640). Они подготовят понятную обратную связь и явное подтверждение действий для сквозного сценария SPEC §4 и единого интерфейса клиента/специалиста (§5 Q55); само подписание останется отдельным сценарием по Q53.

## What Changes

- Добавить доступный баннер с безопасным текстом ошибки и необязательной кнопкой повторного действия.
- Добавить управляемый диалог подтверждения с клавиатурой, фокусом на отмене, ожиданием и защитой повторного действия.
- Покрыть компоненты тестами и проверить нативный диалог в desktop-браузере.
- Описать контракт props для последующего подключения бизнес-страниц.

## Capabilities

### New Capabilities

- `action-feedback`: доступное сообщение об ошибке и явное подтверждение пользовательского действия без зависимости от транспорта и DTO.

### Modified Capabilities

Нет. Существующие вход, транспорт и форматтеры не меняются.

## Impact

Новые общие frontend-компоненты, локальные стили, тесты и README. Используются уже установленные Alfa Typography/Button и нативный HTML dialog; новых зависимостей нет. API, модели, маршруты и права доступа не меняются. Работа в текущей ветке codex/frontend-client-flow.

## Вне скоупа

Автоматические повторы HTTP, обработка доменных кодов/версий, подписание, изменение статусов, фиктивные данные, вызовы backend и подключение компонентов к бизнес-экранам. Архитектурные задачи с generated DTO остаются открытыми до API Dev 2.
