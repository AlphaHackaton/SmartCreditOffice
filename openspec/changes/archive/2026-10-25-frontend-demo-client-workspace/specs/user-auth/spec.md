# Spec Delta

## MODIFIED Requirements

### Requirement: Вход по подтверждённой роли

Требование относится к API-режиму; явно обозначенный mock-режим регулирует demo-client-workspace.

Вход SHALL выполняться через API с тестовыми учётными данными внутри UI. Рабочее пространство SHALL определяться подтверждённой сервером ролью. Выбор подписи или точки входа SHALL не предоставлять права сотрудника.

#### Scenario: Вход сотрудника
- **WHEN** API успешно проверяет учётные данные и подтверждает роль сотрудника
- **THEN** открывается очередь заявок сотрудника без ручного переключения роли

#### Scenario: Ошибка входа
- **WHEN** API отклоняет учётные данные
- **THEN** форма сохраняет введённый логин, показывает понятную ошибку и не открывает защищённые данные

#### Scenario: Выбор входа для сотрудников клиентом
- **WHEN** предприниматель вводит действующие клиентские данные через точку «Вход для сотрудников»
- **THEN** его права остаются клиентскими и интерфейс не открывает служебные данные

### Requirement: Доступность API и демо-учёток

Требование относится к API-режиму; явно обозначенный mock-режим регулирует demo-client-workspace.

Демо-персоны SHALL поступать из локального API, без собственной копии seed-данных во frontend. При недоступности API интерфейс SHALL показывать ошибку соединения и возможность повтора без имитации успешного входа. Пароли и токены SHALL не попадать в логи и постоянное хранилище браузера.

#### Scenario: Сервер недоступен
- **WHEN** запрос входа не может связаться с API
- **THEN** форма остаётся доступной, показывает ошибку соединения и не создаёт сессию

#### Scenario: Демо-персоны загружены
- **WHEN** API возвращает список доступных тестовых пользователей
- **THEN** интерфейс использует этот список без локального дублирования компаний и ожидаемых решений
