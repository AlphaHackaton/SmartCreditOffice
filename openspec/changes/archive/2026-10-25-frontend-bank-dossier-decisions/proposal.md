# Proposal

## Why

Фича №12 завершает банковский путь после работающей очереди №11: SPEC §4, §5 Q4/Q6/Q10/Q37/Q62/Q69/Q73; ARCHITECTURE.md: Dev 3, DossierPage, ScoringTrace, InputsSnapshot, AuditLog, DecisionForm. Сейчас досье — заглушка, bank не может завершить UNDERWRITING.

## What Changes

- Досье исходных примеров и заявок сеанса: профиль, запрос, история, снимки входов, факторы/правила/баллы, рекомендация и политика.
- Только bank: решение APPROVED/COUNTER_OFFER/REJECTED из UNDERWRITING с обязательным комментарием, выбором готовых условий и подтверждением.
- Аудит решения и override; версия/конфликты; связное обновление очереди и клиентской проекции.
- Детерминированное воспроизведение сохранённого снимка без возврата финальной заявки в скоринг.
- Общий mock-store для чтения досье, команд и последующих метрик; существующие клиентские сценарии сохраняются.

## Capabilities

### New Capabilities
- `demo-bank-dossier`: банковское досье, трасса, ручное решение и аудит на синтетических данных.

### Modified Capabilities
- `demo-bank-queue`: строка очереди открывает работающее досье вместо заглушки.

## Impact

Frontend bank/panels, WorkspaceGateway, генератор demo и тесты; новая временная банковская проекция отдельно от клиентской. Python FSM/policy/evaluate — источники истины; scoring не переписывается в JS. HTTP/модели БД не меняются. Проектируемый адаптер будущего API описан в design; реальные DTO только из OpenAPI Dev 2.

## Вне скоупа

Метрики №13, песочница №14, изменение риск-политики/доменных правил, самостоятельный расчёт офферов, новые права/регистрация, реальная подпись/выдача и реализация HTTP API. Планирование не означает выполнения: все задачи остаются открытыми до отдельного apply.
