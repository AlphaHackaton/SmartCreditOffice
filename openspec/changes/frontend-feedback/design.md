# Design

## Context

См. proposal.md. В shared/components уже есть AppLayout и компоненты значений. Alfa Typography/Button установлены и совместимы с React 18; отдельного Modal нет. LoginView демонстрирует защиту повторной отправки через ref и безопасный catch. API Dev 2 ещё отсутствует.

## Goals / Non-Goals

**Goals:** общие компоненты на примитивных props, управление владельцем, доступная клавиатура и безопасное ожидание без новых пакетов.

**Non-Goals:** обработка ApiError/422/409, retry транспорта, подписание, подключение в бизнес-разделы и собственные DTO.

## Decisions

1. ErrorBanner принимает message?: string | null, onRetry?: () => void | Promise<void>, pending?: boolean. Пустой текст ничего не рендерит. Текст выводится React без HTML. Баннер role=alert; кнопка Alfa «Повторить», при ожидании отключена; отдельный role=status сообщает ожидание. Внутренний ref блокирует двойной клик до React-render, состояние удерживается до завершения Promise. Ошибка обработчика перехватывается без вывода деталей; исходное безопасное сообщение сохраняется. Владелец отвечает за текст и допустимость повтора конкретной операции; автоматического вызова нет.

2. ConfirmDialog принимает open, title, description, confirmLabel, cancelLabel? (по умолчанию «Отмена»), pending?, onConfirm: () => void | Promise<void>, onCancel: () => void. Названия/описания — строки, не HTTP DTO. Используем нативный dialog/showModal с Alfa Typography и ButtonDesktop; он помещается в верхний слой и обеспечивает модальность/Tab. При открытии сохраняем инициатор и фокусируем отмену; cleanup закрывает dialog и восстанавливает фокус, если инициатор ещё в документе. Нативный cancel (Escape) перехватывается: вызываем onCancel только вне ожидания. Клик по фону ничего не подтверждает и не закрывает. Управление open остаётся владельцу; успех onConfirm не закрывает компонент самостоятельно.

3. pending либо незавершённый Promise блокирует обе кнопки и Escape. Ref исключает повторную отправку. При отклонении показывается общее сообщение «Не удалось выполнить действие. Попробуйте ещё раз.» и действие вновь доступно. Ошибка очищается перед повтором и при новом открытии. При ожидании фокус остаётся внутри диалога; если кнопка стала disabled, доступен сам dialog (tabIndex=-1). Подтверждение возможно только явным действием на соответствующей кнопке, не открытием или эффектом.

4. Нативный dialog выбран вместо ручного focus trap и новой зависимости Modal. Тестовый jsdom не реализует showModal/close: локальные стабы проверят вызовы и управление состоянием, а реальный desktop-браузер — Tab, Escape, фокус и верхний слой. Временный стенд удаляется до коммита; тестовые операции не добавляются в маршруты приложения.

5. API (эндпоинты/схемы) и модель данных не меняются. Финансовых расчётов/скоринга нет. Новых зависимостей, lock/notices изменений и сервисов compose нет. Компоненты получают только безопасные строки/обработчики и не делают запросов.

## Risks / Trade-offs

- [jsdom не проверяет реальную модальность] → обязательная проверка в desktop-браузере, включая Shift+Tab и возврат фокуса.
- [Пользовательский обработчик повторяет неидемпотентную команду] → компонент не запускает обработчики сам; решение о показе повтора остаётся бизнес-экрану после API.
- [Зависший обработчик] → ожидание управляется Promise/pending; отмена запроса/таймаут принадлежат владельцу операции, не диалогу.

## Migration Plan

Добавить изолированные компоненты/стили/тесты и README, выполнить harness, build и strict validation. Откат — revert frontend-коммитов. Реальные страницы подключат их после появления контракта, без изменения этого примитивного интерфейса.
