# API для следующего этапа Dev 3

Статус на 25.10.2026: API ещё разрабатывается (подтверждено пользователем). Это список потребностей для передачи Dev 2, а не утверждение готового контракта. Сообщения другим участникам автоматически не отправлялись.

Нужно передать:

- Ветку/коммит с `docs/openapi.json`, команду запуска stub API и адрес, обычно localhost:8000.
- Формат входа и проверки текущего пользователя, значения ролей клиента и сотрудника, формат ошибок.
- `GET demo/personas` и тестовые учётки: Sokolova для положительного сценария, underwriter для проверки роли. Фактический login берётся из API (в README — `sokolova`).
- Профиль компании, продукты и ограничения формы, создание/чтение/подачу заявки. Все денежные значения — строки; статусы, версии и история — явные поля.
- APPROVED с клиентскими факторами и оффером: ставка, срок, сумма, платёж, переплата, expiry — готовые значения backend.
- Команды accept/sign, код на экране, неверный код, конфликт версии и истёкший оффер; документированный способ восстановить challenge при повторном входе в SIGNING.
- Работающий переход Соколовой через HTTP: DRAFT → SUBMITTED/SCORING → APPROVED → SIGNING → SIGNED/DISBURSED. SIGNED допускается как промежуточное состояние; выдача — только DISBURSED.
- Детерминированные ошибки 401/403/404/409/422. Изменяющие команды не должны требовать автоматического повтора со стороны frontend.
- Без реальных ФНС/БКИ/банка, SMS/email и вызова платных моделей. Всё на локальных синтетических данных.

Проверка передачи: сгенерировать типы `cd frontend && npm run gen:api`, выполнить typecheck, пройти вход клиента/сотрудника и положительный сценарий через HTTP. Пока это невозможно, интеграцию и весь этап нельзя считать готовыми.
