# Tasks

Dev 3; задачи по 30–90 минут. На момент предложения выполненных задач нет. Этап A не требует API. Этапы B/C начинаются только после задачи 2.1; отсутствие API не считается выполнением этой задачи и не заменяется frontend-заглушкой. После правок — harness_quick_check, перед завершением задачи — harness_check exit 0. Коммиты по завершённым этапам разрешены пользователем.

Критерий: тесты router проходят с новыми названиями, ссылки не меняют адреса, desktop 1280/1440 не перекрывается; `npm run lint && npm run typecheck` проходят.
- [ ] 1.2 (60–90 мин) Создать самостоятельный LoginView с полями логина/пароля, подписью «Вход для сотрудников», внутренним состоянием, props для submit/pending/error и клавиатурной отправкой. Добавить рядом тесты пустых полей, pending, ошибки, сохранения логина и доступных названий; документировать использование. Пока не подключать фиктивную авторизацию и не создавать HTTP DTO. Критерий: компонентные Vitest-тесты проходят без API, пароль не сохраняется в localStorage/логах, состояние успеха не имитируется.

## Workflow follow-up

- После просмотра предложения запустить openspec-apply-change; можно начать с этапа A, пока Dev 2 завершает API.
- Последовательно архивировать завершённые изменения через openspec-archive-change после проверок; основные specs вручную не редактировать.
- Следующее изменение после положительного пути: полноценный контроффер/симулятор и отказ с рекомендациями; затем очередь/досье/ручное решение сотрудника для agroyug и метрики.
