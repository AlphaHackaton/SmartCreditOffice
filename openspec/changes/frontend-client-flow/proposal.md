# Proposal

## Why

Готовый frontend-shell даёт только предварительный просмотр. Следующий этап Dev 3 должен связать вход и клиентские экраны в проверяемый путь Соколовой до выдачи кредита. Основания: SPEC §2.1 и §2.3 (desktop и действия внутри UI), §4 (сквозной процесс), §5 Q53 (подписание внутри продукта), Q55 (роли в одном интерфейсе), ARCHITECTURE:621–690.

## What Changes

- Использовать названия «Сотрудник банка», «Вход для сотрудников» и «Рабочее место кредитного специалиста»; сохранить техническую роль BANK и пути `/bank/*`.
- Подключить вход через API, получение пользователя и роли, защиту клиентских и служебных маршрутов, выход и обработку истечения сессии. Пользователь не назначает себе роль переключателем.
- Добавить кабинет с профилем компании и заявками, форму финансирования и согласия, страницу заявки с историей и ожиданием скоринга.
- Отобразить одобрение, объяснение и условия из backend; принять оффер, подписать кодом внутри UI и показать выдачу только по серверному статусу DISBURSED.
- Для остальных исходов показать безопасные состояния без неуместных действий; полноценный контроффер и рабочее место сотрудника — следующие изменения.
- Интеграцию выполнять только после публикации OpenAPI и stub API Dev 2; пользователь подтвердил, что API ещё разрабатывается.

## Capabilities

### New Capabilities

- `user-auth`: вход, определение роли по серверу, защита маршрутов, выход и пользовательские названия для сотрудников.
- `client-credit-application`: профиль, оформление заявки, отслеживание решения и одобренный путь до выдачи.

### Modified Capabilities

Отсутствуют: основные спецификации ещё не опубликованы. Новый контракт добавляет авторизацию и бизнес-страницы к законченному изменению frontend-shell; его транспорт и правила отображения нереализованных разделов сохраняются.

## Impact

Изменяются frontend/auth, api, client, shared, маршрутизация и тесты; генерируется schema.d.ts из OpenAPI Dev 2. Новые backend endpoint, DTO, модели БД и правила скоринга в рамках Dev 3 не создаются. Предшественник frontend-shell остаётся доступен в истории. Новые зависимости добавляются только с lock-файлом и THIRD_PARTY_NOTICES.md.

## Вне скоупа

Реализация backend вместо Dev 2, ручные DTO, копирование seed-персон, фиктивная выдача, финансовые расчёты во frontend, полноценный симулятор, ручные решения сотрудника и метрики. Нет внешних каналов, мобильной версии и production-интеграций. Контракт и работающий stub — обязательная внешняя зависимость для завершения изменения.
