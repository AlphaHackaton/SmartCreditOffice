# action-feedback Specification

## Purpose

Обеспечить одинаковую доступную обратную связь об ошибках и явное подтверждение действий в клиентском и служебном контурах без зависимости от backend.

## Requirements

### Requirement: Понятное сообщение об ошибке

Баннер SHALL объявлять переданный безопасный текст ошибки вспомогательным технологиям и показывать необязательную кнопку повтора только при наличии обработчика. Пустое сообщение SHALL не создавать пустое оповещение. Разметка в тексте SHALL не исполняться.

#### Scenario: Ошибка с повтором
- **WHEN** переданы сообщение и обработчик повтора
- **THEN** сообщение доступно как alert, кнопка вызывает обработчик только по действию пользователя

#### Scenario: Ожидание повтора
- **WHEN** повтор выполняется либо передан pending
- **THEN** повторная отправка блокируется, ожидание объявляется в UI

#### Scenario: Отклонение повтора
- **WHEN** обработчик отклоняет Promise с технической ошибкой
- **THEN** нет необработанного отклонения, исходный безопасный текст сохраняется, повтор снова доступен

### Requirement: Явное подтверждение

Диалог SHALL иметь доступное название и описание, открываться только по команде владельца и вызывать действие только кнопкой подтверждения. При открытии фокус SHALL переходить на отмену; Tab SHALL оставаться внутри, а закрытие SHALL возвращать фокус инициатору, если он ещё существует.

#### Scenario: Отмена с клавиатуры
- **WHEN** пользователь открывает диалог и нажимает Escape
- **THEN** вызывается отмена, действие не выполняется, после закрытия фокус возвращается инициатору

#### Scenario: Нет автоматического подтверждения
- **WHEN** открывается диалог либо пользователь нажимает Enter на отмене
- **THEN** подтверждаемое действие не выполняется

### Requirement: Одно действие во время ожидания

Подтверждение SHALL блокировать повторные клики, отмену и Escape на время внешнего pending либо Promise обработчика. После ошибки SHALL показываться общее безопасное сообщение, диалог остаётся доступен для повтора. Успешное завершение SHALL не закрывать диалог автоматически: этим управляет владелец.

#### Scenario: Повторный клик
- **WHEN** пользователь дважды подтверждает до завершения первой попытки
- **THEN** обработчик вызывается один раз, виден статус ожидания

#### Scenario: Ошибка действия
- **WHEN** обработчик подтверждения отклоняет Promise
- **THEN** технические детали не отображаются, пользователь может отменить или повторить действие

### Requirement: Независимость от API

Компоненты SHALL работать без сети, backend DTO и бизнес-операций. Повтор SHALL выполняться только по нажатию пользователя; тестовые действия SHALL не монтироваться на бизнес-страницы.

#### Scenario: Изолированный компонент
- **WHEN** компонент открывают с локальным обработчиком
- **THEN** не выполняются HTTP-запросы, переходы статусов или автоматические финансовые действия
