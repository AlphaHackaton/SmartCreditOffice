# AGENTS.md — правила для агентов

## Проект
«Умный кредитный кабинет предпринимателя» (хакатон Альфа-Будущее 2026).
Дедлайн: **26.10.2026 18:00 МСК** — коммиты после не учитываются.
Предметная спецификация: `SPEC_FOR_AGENT.md` (единственный источник истины).
Не загружай её целиком в контекст: делегируй вопросы по ней субагенту `explore`
или ищи grep'ом по разделу (§2 запреты, §4 сценарий, §5 Q&A, §6 чек-лист).

## Роли
- plan — архитектура, OpenSpec-предложения. Код не пишет.
- build — реализует задачи из `openspec/changes/<id>/tasks.md`.
- explore — чтение кода и SPEC, ответы с цитатами и номерами строк.

## Стек (не менять без OpenSpec-изменения)
- backend/: Python 3.12, uv, FastAPI, Pydantic v2, SQLAlchemy 2 + Alembic, PostgreSQL 16, pytest, ruff, mypy.
- frontend/: React 18 + TypeScript (strict) + Vite, @alfalab/core-components, TanStack Query, react-router, eslint, vitest.
- Инфраструктура: docker-compose (db, backend, frontend). LLM — опционально, только OpenAI-совместимый клиент
  с env `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`; без LLM всё обязано работать (fallback на правила).

## Жёсткие запреты (из SPEC §2) — нарушение = провал проверки
1. Только десктопный Web. Никаких мобильных приложений.
2. Никаких платных/закрытых API в рантайме (OpenAI, Claude, GigaChat, Yandex OCR). Только open-weights модели.
3. Никаких SMS/email/звонков/Telegram в сценарии: вход и подпись — только внутри UI (код на экране/кнопка).
4. Ничего тяжёлого в docker-compose: проверка на CPU-only, 8–12 ГБ RAM. Не класть веса моделей в образ/репо.
5. Все внешние системы (ФНС, БКИ, CRM, выручка) — локальные моки в `backend/app/mocks/`.
6. Не делать: новостную ленту, регистрацию юрлица, OCR, адаптивную вёрстку, лендинг.

## Доменные инварианты
- Сквозной сценарий: Потребность → Заявка → Скоринг (моки) → Решение → Подписание → «Кредит выдан».
- Три исхода решения: APPROVED / COUNTER_OFFER / REJECTED. Каждое решение хранит объяснение
  (входные факторы, баллы, правило) — прозрачность обязательна.
- Статусы заявки — явный конечный автомат в одном модуле (`backend/app/domain/application_status.py`),
  переходы только через него, история переходов сохраняется.
- Ставки рыночные (от ключевой ставки ЦБ, задаётся в конфиге), без фантастических условий.
- Роли «Клиент» / «Банк» в одном интерфейсе; тестовые учётки из seed-данных.

## Процесс работы
1. Любая фича или изменение API/модели данных → сначала OpenSpec (`/opsx-propose`), потом `/opsx-apply`.
   Мелкие фиксы (≤ 1 файл, без смены контракта) — без OpenSpec.
2. После каждой правки читай блок `[harness quick-check]` в выводе инструмента и исправляй ошибки сразу.
3. Перед тем как сказать «готово» по задаче: вызови инструмент `harness_check`; задача закрыта только при `exit 0`.
4. Не отключай проверки (`# noqa`, `eslint-disable`, `@ts-ignore`, `skip`) без комментария-обоснования.
5. Новая зависимость → обнови lock-файл (`uv.lock` / `package-lock.json`) и `THIRD_PARTY_NOTICES.md`.
6. Изменил API → `scripts/check.sh` перегенерирует `docs/openapi.json`; закоммить его.
7. Коммиты маленькие, Conventional Commits (`feat:`, `fix:`, `chore:`), только по просьбе пользователя.

## Границы
- Не трогать: `SPEC_FOR_AGENT.md`, `QUICK_GUIDE.md`, `src/`, `.git/`, `openspec/specs/` вручную (только через archive).
- Без подтверждения не выполнять: `git push`, `rm -rf`, `docker system prune`, удаление миграций.
- Секреты только в `.env` (в git — `.env.example`).

## Команды
- Полная проверка: `bash scripts/check.sh`
- Backend dev: `cd backend && uv run uvicorn app.main:app --reload`
- Frontend dev: `cd frontend && npm run dev`
- Всё: `docker compose up --build`
