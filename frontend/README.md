# Frontend — кредитный кабинет

Node.js 22.12+ (проверено на 24.21), React 18, TypeScript strict, Vite, Alfa Core Components, TanStack Query и react-router. Из корня:

```bash
npm ci --prefix frontend
npm run dev --prefix frontend
npm test --prefix frontend -- --run
npm run lint --prefix frontend
npm run typecheck --prefix frontend
npm run build --prefix frontend
```

http://localhost:5173. Только desktop; API, БД и LLM для демо не нужны. Используются официальные отдельные Alfa-пакеты: React 18 совместим, конфликтующий umbrella-пакет не подключён. Стили локальные, загрузки CDN/шрифтов нет.

## Демо и API

По разрешению пользователя интерфейс развивается на изолированных моках. По умолчанию включён явно обозначенный mock-режим, можно задать `VITE_DATA_MODE=api` при запуске Vite. Панель «Управление демо» переключает режим, задаёт задержку 0/400/1500 мс, одноразовый сбой следующего чтения (401/403/404/503) или команды (409/422/503), сбрасывает демо после подтверждения. Смена режима и сброс очищают сессию/кеш. Перезагрузка удаляет все данные в памяти.

API Dev 2 ещё не опубликован. Режим API сообщает об этом и не подставляет моки. `src/demo/gateway.ts` определяет временные модели представления и интерфейс адаптера, не HTTP DTO. Будущий адаптер преобразует generated DTO в эти модели. Мок-режим не считается подтверждением сквозной HTTP-интеграции.

## Данные и домен

```bash
npm run gen:demo --prefix frontend
```

Генератор `scripts/export_frontend_demo.py` читает backend seed, POLICY_V1, enum и FSM и создаёт `src/demo/generated.ts`. Персоны/продукты/статусы не переписываются вручную; истории проверяются настоящим Python FSM. В браузер попадают публичные профили и готовые последовательности стадий, без банковской трассы. Для произвольных условий финал демо — ручное рассмотрение, без локального расчёта решения.

Полная проверка выполняет генератор с `--check`: изменение backend seed/enum/политики без регенерации frontend-артефакта завершает harness с ошибкой. Таким образом, устаревшие фикстуры не проходят проверку.

MockGateway хранит данные и сессии только в памяти, проверяет роль/владельца/version, возвращает копии, отменяет чтения через AbortSignal, отклоняет старые команды после reset и не повторяет команды автоматически. BigInt используется только для точной проверки границ/шага ввода; ставки, платежи и скоринг в JS отсутствуют.

## Вход и навигация

`/login` подключён к готовой LoginView. Демо-учётки загружаются адаптером: `p1`…`p6` из backend seed, сотрудник `underwriter`; пароль `demo`. Можно войти формой или кнопкой персоны. Это синтетическая демонстрация, реальные пароли вводить не нужно.

AuthProvider проверяет текущего пользователя через адаптер и определяет роль по ответу; подпись «Вход для сотрудников» прав не выдаёт. RequireRole блокирует защищённые запросы до подтверждения пользователя. Путь после входа восстанавливается только внутри собственного контура; внешние URL, traversal и адреса чужой роли отклоняются. Выход/401 отменяют запросы и очищают кеш, запоздалый вход после выхода/reset сессию не создаёт. Пароль и токен не сохраняются в localStorage/sessionStorage.

Клиент: `/client`, `/client/applications/new`, `/client/applications/:id`. Сотрудник: `/bank/applications`, `/bank/applications/:id`, `/bank/metrics` — пока честные заглушки, полноценный служебный контур в следующих фичах. Переключателя прав в layout нет, доступны только ссылки своей роли. Неизвестный адрес — 404.

## Общие компоненты

- `shared/format.ts`: formatMoney, formatPct, formatDate, formatDateTime. Денежные строки без Number/parseFloat, две копейки и U+00A0; лишняя точность отклоняется. Проценты без умножения на 100/округления. Календарь YYYY-MM-DD без сдвига, события с timezone — Europe/Moscow. Неверные/пустые значения → `—`.
- MoneyText(value) и DateTimeText(value, kind='timestamp'|'date'): табличные цифры, семантический time/dateTime и доступное описание недоступных данных.
- ErrorBanner(message, onRetry?, pending?): безопасный alert, повтор по нажатию, защита дублей и отклонения Promise.
- ConfirmDialog(open, title, description, confirmLabel, onConfirm, onCancel, pending?): Alfa-кнопки и нативная модальность, фокус отмены, Tab/Shift+Tab внутри, Escape/возврат фокуса, блокировка во время Promise и безопасная ошибка. В jsdom модальность проверяется отдельной заглушкой; браузерная проверка обязательна.

## HTTP-транспорт и будущий OpenAPI

`useApiClient()` — `/api/v1`, Bearer из памяти, JSON со строками сумм, AbortSignal, запрет внешнего URL/traversal/redirect. ApiError сохраняет status/code/message/details; 204 возвращает undefined, плохой JSON — INVALID_RESPONSE, сеть — NETWORK_ERROR. Только 401 текущей сессии очищает токен/кеш; 403/409/422 его сохраняют. Отменённый запрос не превращается в сетевую ошибку, автоматических повторов команд нет. Vite проксирует `/api` на localhost:8000.

```bash
npm run gen:api --prefix frontend
```

Генерирует `src/api/schema.d.ts` только из настоящего `docs/openapi.json`. При отсутствии экспорта Dev 2 команда возвращает понятную ошибку; при ошибке сохраняет прежний результат. Фиктивного OpenAPI нет. Финальная адаптация auth/команд/версий к HTTP требует отдельной проверки после передачи API.

Сведения о зависимостях: `npm run notices --prefix frontend`, версии фиксированы package-lock.json.

## Статусы и история

`shared/status.ts` исчерпывающе покрывает союз из backend-экспорта. StatusBadge(status) показывает русское название и различимую цветовую категорию; неизвестное runtime-значение отображается без команд. Timeline(history, current) содержит только пришедшие события с московскими датами, участником и aria-current для текущего события; будущие этапы и выдуманный процент не рисуются.

## Кабинет клиента

DashboardPage независимо загружает профиль, продукты и заявки через TanStack Query. Ключи включают режим, поколение демо и пользователя; AbortSignal отменяет чтения. Ошибка одной секции не скрывает остальные, повтор выполняется кнопкой. Продукты показывают границы политики без выдуманной ставки/предодобренного лимита. Выбор продукта передаёт query-параметр форме; список заявок ведёт на прямые адреса. Новая компания начинает с пустого списка.

## Новая заявка и черновики

NewApplicationPage принимает `?product=CODE` или `?draft=ID`. Поля: продукт, сумма-строка, целый срок, цель, согласия БКИ/ПД. Границы и шаг берутся из политики backend. Черновик можно сохранить без согласий; подача требует оба. Ошибка 422 показывается у поля без потери ввода. Повтор после неудачного submit обновляет тот же draft, не создаёт второй. Version проверяется адаптером; при конфликте читается актуальная версия без автоматического повтора команды. После успешной подачи открывается возвращённый id; двойной клик блокируется. Смена пользователя/уход со страницы не позволяют запоздалой мутации перенаправить новый экран.

## Страница заявки

ApplicationPage читает собственную заявку, показывает запрошенные условия, текущий статус и Timeline. Для DRAFT доступно продолжение по `?draft=ID`. Только SUBMITTED/SCORING опрашиваются каждые 1500 мс; ошибка, результат, logout или уход прекращают опрос. Ошибка чтения повторяется явно; 403/404 скрывают данные. Неизвестный runtime-статус не открывает действия. Демо воспроизводит backend-историю до APPROVED/COUNTER_OFFER/REJECTED/UNDERWRITING; офферы, подписание, симулятор и реальные банковские команды относятся к следующим фичам.

## Проверенный браузерный сценарий

25.10.2026, desktop 1280×900 и 1440×900: открыть /client → вход p1 → профиль/продукты/пустые заявки → новая заявка → подача без согласий отклоняется → сохранение черновика → оба согласия → подача → история SUBMITTED/SCORING/APPROVED. Проверены одноразовый сбой чтения, независимость секций, сброс с подтверждением и выходом, вход underwriter и переключение mock/API. Перекрытий и ошибок консоли нет. Воспроизводимые состояния гонок, поллинга, version и 422 покрыты Vitest.

## Фича 7: одобрение и офферы

DecisionPanel/FactorList показывают публичные объяснения Python, OffersList — готовые денежные строки, ставку, срок, платёж, переплату и срок действия (в демо 30 минут). Выбор подтверждается диалогом, accept защищён owner/version/status/expiry; 409 перечитывает запись без повторной команды. Клиент не получает rule_id, raw values, score или банковские входы.

## Фича 8: подписание и выдача

После accept открывается SigningPanel с неизменяемыми выбранными условиями и кодом 123456 внутри UI. Подтверждение живёт 5 минут, допускает 3 неверных попытки; после блокировки новый сценарий начинается сбросом демо. Возврат по адресу восстанавливает challenge в текущей сессии. sign возвращает SIGNED, опрос через 1500 мс получает DISBURSED и останавливается. Только этот статус открывает «Кредит выдан». Это виртуальная подпись/выдача без внешних каналов.

## Фича 9: контроффер и симулятор

COUNTER_OFFER показывает исходный запрос, готовые альтернативы и ограничивающие условия Python. Симулятор есть также при APPROVED: debounce 300 мс, отмена предыдущего чтения, состояние обновления без устаревшего прогноза. Сумма передаётся строкой, срок — целым; выберите подготовленную сумму из списка и срок ползунком. В сетке исходная/минимальная/половинная/альтернативные суммы и все сроки с шагом 6; другие комбинации дают явную ошибку «нет демо-расчёта». Результаты simulate заранее экспортированы Python, не меняют заявку и не создают принимаемый оффер. Ограничения подсвечены, деньги/ставки/платежи в JS не вычисляются.
