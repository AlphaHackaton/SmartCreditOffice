# Frontend — кредитный кабинет

Нужен Node.js 22.12+ (проверено на 24.21). Из корня репозитория:

```bash
cd frontend
npm ci
npm run dev
```

Открыть http://localhost:5173. Backend, БД и LLM для каркаса не нужны.

```bash
npm run lint
npm run typecheck
npm run test -- --run
npm run build
npm run preview
npm run notices
```

React 18 и официальные отдельные пакеты Alfa Core Components используются по решению команды: общий пакет 50.38.0 тянет устаревший react-virtual с peer React 16/17. Отдельные Typography/Button/Vars поддерживают React 18. Стили импортируются из поставляемых пакетов; сборка не загружает шрифты/CDN.

Это предварительный просмотр каркаса. Реального входа, RBAC, данных компаний и банковских операций пока нет. Токен будущей сессии хранится только в памяти; при смене сессии кеш отменяется и очищается. QueryClient создаётся один раз на приложение, автоматические retry отключены. Перезагрузка страницы сбрасывает сессию.

## Навигация

Адреса: `/client`, `/client/applications/new`, `/client/applications/:id`, `/bank/applications`, `/bank/applications/:id`, `/bank/metrics`, `/login`. Корень ведёт в клиентский кабинет; неизвестный адрес — на 404. Меню «Клиент / Сотрудник банка» переключает только предварительный просмотр, а не права действующего пользователя.

Проверка в браузере: desktop iframe-viewport 1280×900 и 1440×900 — меню и контент не перекрываются; прямой адрес `/bank/applications/qa-case` сохраняется после refresh; Tab/Enter переводят из очереди в метрики. Автотесты дополнительно проверяют все маршруты, aria-current, landmarks, клавиатуру и отсутствие API-запросов. Production history fallback добавит Dev 2 при подключении nginx.

## HTTP и сессия

`useApiClient()` возвращает транспорт с базой `/api/v1`, методами GET/POST/PATCH/PUT/DELETE, JSON-body и AbortSignal. Результат — `unknown`; реальные DTO появятся после генерации из API Dev 2. Денежные строки сохраняются. Запрещены абсолютные URL и выход из префикса; redirect отключён. Vite проксирует `/api` на `http://localhost:8000`; CORS для локальной разработки не нужен.

Ошибки: `ApiError {status, code, message, details}`. 204 — `undefined`; повреждённый успешный JSON — `INVALID_RESPONSE`, недоступная сеть — `NETWORK_ERROR`. AbortError не превращается в серверную ошибку. При 401 текущей сессии токен удаляется, запросы отменяются, кеш очищается и открывается `/login`; запоздалый 401 старого пользователя не сбрасывает новую сессию. При 403/409/422 сессия сохраняется. Ошибочные команды не повторяются автоматически. API и модели backend этим изменением не меняются.

## Типы из OpenAPI

Dev 2 публикует экспорт API в `docs/openapi.json` в корне репозитория. Затем из frontend:

```bash
npm run gen:api
```

Результат — `src/api/schema.d.ts`; его не редактируют вручную. При отсутствии экспорта команда завершается с ненулевым кодом и сообщением «Нужен docs/openapi.json от Dev 2». При ошибке ранее сгенерированный файл сохраняется. Тесты генератора используют только временные синтетические схемы и не создают доменный контракт в docs.

Сейчас backend API и его экспорт отсутствуют. Каркас не импортирует несуществующие типы и проходит build/typecheck/test без них. Следующее изменение подключит сгенерированные DTO, реальный вход, RequireRole и бизнес-хуки к stub API. Для этого изменения API, моки и модели БД не создаются.

Служебный контур обозначен как «Рабочее место кредитного специалиста», доступная навигация — «Разделы сотрудника банка». Это изменение пользовательских названий: роль и пути `/bank/*` сохраняются.

## Подготовка входа (этап A)

`src/auth/LoginView.tsx` — самостоятельная форма на Alfa InputDesktop/ButtonDesktop с локальным состоянием. Она пока не подключена к маршруту `/login`: LoginPage и фактическая авторизация требуют OpenAPI и stub Dev 2. Предварительный просмотр существующих контуров сохранён.

Props:

- `onSubmit({ login, password })`: обязательный обработчик; для асинхронной попытки возвращает Promise<void>. Это внутренние значения формы, не HTTP DTO. Логин обрезается по краям, пароль передаётся без изменения.
- `pending`: внешнее ожидание, блокирует поля/кнопки и повторную отправку. Во время Promise от onSubmit повторная отправка также блокируется самой формой.
- `error`: безопасное сообщение владельца формы. Необработанное отклонение onSubmit превращается в общее сообщение без вывода деталей ошибки.
- `initialAudience`: `client` (по умолчанию) или `employee`. Переключение подписи «Вход для сотрудников» меняет только текст, не назначает роль и не добавляет её в данные submit.

Пустые поля проверяются до обработчика, фокус переходит к первому некорректному полю. После попытки входа пароль очищается, логин сохраняется; при смене контекста пароль также очищается. Форма сама не обращается к сети, не создаёт сессию, не записывает пароль/токен в хранилище и не показывает успешный вход.

Проверено в браузере на отдельном временном стенде без API: пустые поля, фокус ошибки, Enter, ошибка подключения, контекст сотрудника и desktop 1280/1440. В консоли ошибок нет. Временный стенд удалён; в приложение не добавлялись фиктивные учётки или сервис входа. Компонентные тесты покрывают ожидание, двойной клик, повтор после ошибки и отсутствие записи секретов в хранилище/логи.

## Форматирование значений

`src/shared/format.ts` работает со строками, `null` и `undefined`, без API и финансовых расчётов:

- `formatMoney('9007199254740993.01')` → `9 007 199 254 740 993,01 ₽`. Сумма сохраняется без Number/parseFloat, копейки дополняются до двух знаков. Разряды и знак рубля отделяются неразрывным пробелом U+00A0.
- `formatMoney('-0012.5')` → `-12,50 ₽`; отрицательный ноль отображается как `0,00 ₽`.
- `formatPct('0.1250')` → `0,125 %`, `formatPct('21.000')` → `21 %`. Конечные дробные нули удаляются, умножения на сто и округления нет.

Допустимы десятичные строки с необязательным минусом. Пробелы, запятые, плюс и экспонента не принимаются; деньги с более чем двумя дробными знаками отклоняются, а не округляются. Некорректные и отсутствующие значения возвращают `—`, в том числе при неверном runtime-типе. Эти функции только отображают значения и не нормализуют ввод формы.

`formatDate('2026-10-25')` → `25.10.2026`: календарные даты строго `YYYY-MM-DD`, годы 0001–9999, без перевода часового пояса. Несуществующие дни (включая 29 февраля невисокосного года) возвращают `—`.

`formatDateTime('2026-10-24T22:30:00Z')` → `25.10.2026, 01:30`: события всегда отображаются в `Europe/Moscow`, независимо от настроек устройства. Принимается полная ISO-метка `YYYY-MM-DDTHH:mm:ss` с необязательными долями секунды и обязательным `Z` либо `±HH:mm`. Неверные календарные/временные поля и метки без timezone возвращают `—`. Минуты отображаются без округления секунд.

Проверка независимости от timezone: `TZ=UTC npm test -- --run src/shared/format.test.ts` и `TZ=Asia/Tokyo npm test -- --run src/shared/format.test.ts` из frontend.
